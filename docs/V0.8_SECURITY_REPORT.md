## 3. Cryptographic Provenance Architecture

### 3.1 Dual Jurist Signoff Proof Hash
All finalized Class D rulings compute an immutable SHA-256 seal:
$$\text{ProofHash} = \text{SHA256}(\text{caseId} : \text{primaryScholarId} : \text{primaryResponse} : \text{secondaryScholarId} : \text{secondaryConcurrenceNotes} : \text{secondarySignedAt})$$
This guarantees that once both scholars have signed off, the determination cannot be tampered with in transit or storage.

### 3.2 Session & Refresh Token Hashing
As verified in Database Migration 016, all persistent refresh tokens and session identifiers are stored exclusively as salted SHA-256 digests, eliminating plaintext credential leakage risks.

## 4. Personalization & Memory Controls

AMAL OS adheres to privacy-by-design for all context and memory signals:
- **No Hidden Profiling:** Every memory signal (L1 journey, L2 preference, L3 derived insight) is exposed via `GET /api/v1/memory`.
- **Explicit Confirmation:** AI candidates cannot be promoted into permanent L2 memory without user confirmation (`POST /api/v1/memory/:id/confirm`).
- **Full User Control:** Users can edit any memory value (`PATCH /api/v1/memory/:id`) or delete it permanently (`DELETE /api/v1/memory/:id`).
- **Complete Erasure:** Account deletion (`POST /api/v1/privacy/delete-account`) purges all user memories, sessions, and reflections across all tables and caches.
